# 资料工作台后续实施计划

## 已完成的实践验收

V0.4 同域采集服务已支持公开来源的二次文件发现、候选验证、失效直链恢复、流式下载和 ZIP。真实 Europe PMC 全文 XML 与 Zenodo PDF 已下载验证；Internet Archive 在当前网络超时，不算真实验证通过。新增实际操作验收覆盖页面提交检索、全文下载、即时文件格式、真实 ZIP 与刷新恢复，并修复了二次发现后列表格式未即时更新的问题。

GitHub Pages 不能运行服务；完整功能已经通过同域 Node.js 服务部署到 Render。GitHub Pages 保留静态入口，文件发现、跨域下载和后续后台任务由完整服务承担。

## V0.5 第一批：项目与清单管理

已实现：

- 新建、重命名、切换独立研究项目，旧清单迁入默认项目。
- 每项目最近 5 次检索快照及离线恢复。
- 收藏、个人备注、文件获取信息和 AI 总结保留。
- 来源、类型、年份、关键词等筛选状态按项目保存。
- 追加筛选直接作用于当前清单，不调用模型和来源。
- CSV、JSON、Markdown 导出及全局备份兼容。
- 限制保存规模，空间不足时回滚存储变更；损坏数据保留供恢复。

验收：至少两个项目分别检索不同主题，切换及刷新后清单隔离；收藏和备注保留；历史恢复不发网络请求；示例模式不覆盖项目；导出与备份不包含模型密钥；窄屏布局和既有下载链路通过回归。

当前边界：20 个项目、每快照 200 项、每项目最近 5 次历史。项目仅保存在当前浏览器；备份可以跨设备迁移，尚无云端项目同步。

实践中修复：追加筛选只保存为项目当前视图，不覆盖历史检索时的筛选条件；历史中的收藏、备注和已发现文件信息仍随整理更新，恢复后无需再次采集。

## V0.6：已完成分页迭代、数量控制与模型网页发现

本批已完成各内置来源分页、游标恢复、去重、数量与运行上限、模型候选网页实际验证、关键词扩展、自动二次文件查找；详见 [采集指南](research-collection.md)。真实 Europe PMC 已从首批继续到 50 项、刷新后到 70 项。当前清单仍限制 200 项。

后续实施顺序：

1. 已完成：为每个来源保存独立页码或游标及耗尽状态；Crossref 使用 cursor，Europe PMC 使用 cursorMark，DataCite 和 Internet Archive 使用页码。自定义来源只有声明了分页参数才提供继续加载。
2. 已完成：“继续采集”沿用已经解析的主题、来源和类型，只请求下一页；失败来源保留原游标，重试不跳页。
3. 已完成：增量合并 DOI 和规范化 URL；保留已有收藏、备注、总结和已验证文件地址。
4. 新增/更新标记及重新检查首页，明确区分“继续加载”与“刷新新资料”。
5. 将较大清单和历史迁到 IndexedDB，避免继续增加 localStorage 上限；提供可恢复迁移和版本校验。

验收：真实 API 连续两页返回不同资料；合并后无重复；刷新后能继续下一页；暂停、取消及来源错误不推进游标；不丢失旧清单或用户整理信息。

## V0.8：流式结果与受控研究 Agent

目标是缩短首次等待，同时保证论文、图片、视频、数据等类型的覆盖。检索不再等待“全部抓取并审核完成”后统一展示，而是采用可追踪的状态流程：规划需求、按类型采集、即时展示、后台审核、覆盖检查与缺口补搜。

完整的节点、状态、事件协议、评分方法和验收场景见 [流式研究 Agent 完整流程](research-agent-architecture.md)。

实施顺序：

1. 来源每返回一条合格候选就立即加入清单，初始状态显示为“待审核”；抓取、文件发现和模型审核不再阻塞首批结果。
2. 智能审核在后台分批运行，只更新契合度、理由、审核状态和排序。只有明显无关的结果才隐藏；信息不足、图片元数据较少和边界结果继续展示并标记待确认。
3. 排名按小批次刷新并保持当前滚动位置、勾选状态与焦点，避免每返回一条就剧烈跳动。用户可以在采集未完成时筛选、收藏、查看详情和下载已经就绪的资源。
4. 引入类型配额和覆盖矩阵。用户没有限定类型时，为论文、图片、视频、数据集、网页/报告分别设置最低目标；单一来源或单一类型不能提前占满总数量。
5. 研究 Agent 为不同类型生成独立关键词并选择匹配来源。每轮检查覆盖缺口，只对缺少的类型换关键词、换来源补搜，并受轮次、请求数、时间和最大结果数约束。
6. 记录每条结果的阶段时间：发现、展示、审核、文件验证。控制台按类型显示已找到、已通过、待确认和缺口数量。

体验目标：普通公开主题在来源正常时尽快出现首批可用结果；用户无需等待全量审核。采集过程中清单持续增加，审核后契合度和排名逐步稳定。任务结束时给出各类型覆盖情况、失败来源和仍需补搜的缺口。

验收：宽泛主题不能被单一类型占满；至少覆盖所有有可用来源的核心类型；候选出现后可立即操作；后台审核不会清空或重建整张列表；排序更新不丢失滚动位置、选择、收藏和备注；暂停与取消后保留已经展示的结果。

## V1.0：持久后台任务

按依赖逐项实施：

1. 服务端持久任务库、来源级并发和限流。
2. 失败重试与指数退避，任务日志和取消语义。
3. 浏览器关闭后继续执行，重新连接查看真实状态。
4. 支持 Range 的文件断点续传、长度/哈希校验与临时文件清理。
5. 大文件和大批量下载：后端生成 ZIP，附带来源、许可和失败清单。

验收：重启服务、断网恢复和取消任务均有确定结果；不将部分文件标记为成功；已完成文件不重复下载；任务与用户项目权限隔离。

## 每批交付流程

实现 → 自动回归 → 真实来源实际操作 → 修复发现的问题 → 保存截图和报告 → 更新 PR 和本计划。公开网络失败单独记录；只有实际通过的来源和操作才能计入完成项。
